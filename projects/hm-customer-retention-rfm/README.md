# H&M 客户复购结构分析：同期群留存 + RFM 分层

> 🚧 进行中 · 2026 年 8 月 · SQL + Python（不使用任何机器学习模型）

基于 H&M 真实交易数据（2018–2020，约 137 万客户、三千余万条交易），回答时尚电商最核心的问题：**这门生意到底是靠老客复购，还是靠不断拉新？**

## 一、业务问题

1. 客户的复购结构长什么样？一次性购买客群占比多少，贡献了多少收入？
2. 同期群（cohort）留存曲线如何衰减？第 N 月留存率是多少？
3. 哪些品类 / 价位带是「复购引擎」，哪些只是一次性流量生意？
4. 沉睡 6 个月以上的客群规模多大，值不值得做召回？

对应真实岗位场景：跨境电商 / 用户增长分析师的存量经营分析（SHEIN、Shopee 类业务的复购与留存诊断）。

## 二、数据来源

- [Kaggle – H&M Personalized Fashion Recommendations](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/data)
- 三张表：交易（transactions）、商品（articles）、客户（customers）
- 数据窗口：2018-09 至 2020-09；交易表约 3.7GB，需分块读取
- 说明：该数据在全网几乎只被用于推荐系统竞赛，本项目**只做留存与分层分析，不涉及任何建模**——这正是本项目的差异化定位

## 三、分析框架

| 步骤 | 内容 |
|---|---|
| 1. 明确分析目标 | 量化复购结构，定位复购驱动因素，评估沉睡客群召回价值 |
| 2. 数据清洗与探索 | 大文件分块读取与列裁剪；客户年龄异常值处理；三表关联校验 |
| 3. 拆解问题维度 | 同期群 / 购买频次档 / 品类 / 价位带 / 客户年龄段 |
| 4. 归因与趋势 | 同期群留存矩阵、复购间隔分布、RFM 分层、品类帕累托 |
| 5. 结论与建议 | 输出客群运营建议（召回窗口、券策略、品类组合），并说明局限 |

## 四、SQL 清单（规划中）

| # | 查询 | 技术点 |
|---|---|---|
| 1 | 三表关联，构建客户-订单宽表 | 多表连接（transactions × articles × customers） |
| 2 | 按首购月分组的同期群月留存矩阵 | 窗口函数 + 条件聚合 |
| 3 | 客户复购间隔分布（首单到次单天数） | 窗口函数 `LAG()` |
| 4 | RFM 三维度打分与客户分档 | `CASE WHEN` + 分位数 |
| 5 | 品类销售额帕累托分析（累计占比 TopN） | 窗口函数 `SUM() OVER()` |
| 6 | 沉睡客群（180 天未购）规模与历史价值 | 子查询 + 日期差计算 |

## 五、Python 清单（规划中）

- **3.7GB 交易表分块读取（`chunksize`）+ 只保留分析所需列**——真实的大数据处理工程场景
- 客户年龄缺失与异常值（>100 岁）处理，自定义分箱函数
- `qcut` 完成 RFM 分位打分，`pivot_table` 输出分层客群矩阵
- 自定义函数定义「沉睡客群」并计算其历史贡献
- Matplotlib / Seaborn 绘制留存热力图与帕累托曲线
